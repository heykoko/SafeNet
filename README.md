# SafeNet

An open case study that takes an AI assistant feature from risk assessment to a
written safety policy, tests that policy against a labeled synthetic dataset,
and revises it where it breaks.

> **All data in this project is synthetic.** Every prompt is invented, mild and
> abstract. It names a topic or intent and contains no operational detail, real
> people or explicit content. This project does not collect, store or handle
> real harmful content or real user data. If you contribute prompts, keep to
> the same standard.

## Method

1. **Risk assessment:** [`risk-assessment/risk_register.md`](risk-assessment/risk_register.md)
2. **Policy:** [`policy/policy_v1.yaml`](policy/policy_v1.yaml), with changes recorded in
   [`policy/CHANGELOG.md`](policy/CHANGELOG.md)
3. **Dataset:** synthetic candidates are generated, then hand-reviewed and hand-labeled
   into [`data/test_set.csv`](data/test_set.csv)
4. **Evaluation:** an LLM classifies each prompt against the policy, and the results are
   compared to the hand labels
5. **Revision:** the policy is revised from the disagreements, and the new version is
   compared against the old one

### Running it

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...        # read from the environment, never committed

# 1. candidate prompts -> data/candidates.csv (review, edit, set keep=y, label)
python scripts/generate_candidates.py --policy policy/policy_v1.yaml
python scripts/generate_candidates.py --promote          # keep=y rows -> data/test_set.csv

# 2. classify -> eval/results_v1.csv
python eval/run_eval.py --policy policy/policy_v1.yaml

# 3. report -> eval/reports/report_v1.md (+ disagreements_v1.csv)
python eval/report.py --policy policy/policy_v1.yaml
python eval/report.py --policy policy/policy_v1.yaml --consistency --generate-only  # review data/paraphrases.csv
python eval/report.py --policy policy/policy_v1.yaml --consistency

# 4. after writing policy_v2.yaml and running run_eval.py on it
python eval/report.py --policy policy/policy_v1.yaml --compare policy/policy_v2.yaml
```

Every script takes `--mock`, which runs the pipeline with a deterministic fake model,
with no API key and no cost. Its numbers mean nothing. Other options: `--model`
(default `claude-sonnet-5-5`), `--effort`, `--workers`, `--no-fallback`.

Notes on the evaluation:

- **Labels:** `my_label` is the decision (`allow` / `label` / `limit` / `escalate`), and
  `my_clause_id` is the clause, left empty or set to `NONE` when no clause applies.
  Only labeled rows are scored.
- **Refusals:** the classifier model can itself decline a prompt. By default the API's
  server-side refusal fallback retries on another model, and the `served_model` column
  shows which model answered. A prompt still refused after that is recorded in the
  results and listed in the report, never dropped. Pass `--no-fallback` to measure the
  raw refusal rate.
- **Policy versions:** keep `clause_id`s stable across versions where you can. The
  comparison looks up each label's category in each version's YAML.

## Repository layout

```
risk-assessment/risk_register.md   harm / example / likelihood / severity / mitigation
policy/policy_v1.yaml              policy template (clauses, decisions)
policy/CHANGELOG.md                per-version change log
data/test_set.csv                  id, prompt, my_label, my_clause_id, borderline, notes

eval/run_eval.py                   LLM classification -> eval/results_<version>.csv

eval/safenet_common.py             shared policy / CSV / Claude client code
```
